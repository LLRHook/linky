# Instagram caption translation

## Why a separate translator is needed

OGInstagram, served at `oginstagram.com`, supplies original captions. It has no translation modifier. Asked for `application/activity+json`, its post URL (`/p/{shortcode}/`, or `/reel/{shortcode}/` for Reels) returns an ActivityStreams `Note`: `attributedTo` names the account, `content` holds a statistics paragraph followed by the caption as HTML, and `attachment` lists each item's media type. Linky accepts a Note only when its `id` names the requested shortcode on that origin and its account name is a valid Instagram username. It drops the statistics paragraph and reduces the HTML to plain text before translation; escaped markup in a caption stays literal text. Gallery mode on `g.oginstagram.com` suppresses the caption while retaining provider media. These are unversioned provider interfaces, so requests are bounded and failures leave normal preview handling available. The provider's gateway allows an unverified automated client 50 requests per address per hour ([commit c790ec7](https://github.com/seirenkr/OGInstagram/commit/c790ec7)); Linky caches a caption for five minutes and a failed lookup for 30 seconds, and a refused lookup shows the provider's normal preview with no translated caption. [OGInstagram source](https://github.com/seirenkr/OGInstagram).

Linky uses Google Cloud Translation Basic v2 with `target: "en"` and `format: "text"`. Omitted `source` enables language detection. Paragraphs are translated independently so an English introduction does not hide a foreign-language body. English paragraphs and non-prose separators remain unchanged. Caption URLs, handles and hashtags must survive translation intact; ambiguous or malformed results are discarded. [Translation API](https://docs.cloud.google.com/translate/docs/reference/rest/v2/translate).

A single translated post appears as one Linky block: the author, the English caption excerpt, a small source-language label and a gallery of every item, using the signed `/offload/{shortcode}/{n}` address the Note lists for each attachment. Discord fetches those addresses through its media proxy; the provider redirects them to Instagram's CDN for Discord's agent, and Cloudflare challenges other agents. The block is kept only after Discord reports each item as fetched with its media type. Several links, a Note without an offload address for every item, or more than ten items keep the English excerpt in message text beside the provider's native gallery preview. The gallery is a mode of the same provider, not an independent fallback, and no second Instagram provider is configured. A normal embed containing the original caption cannot count as a translated-preview success. [OGInstagram gallery documentation](https://github.com/seirenkr/OGInstagram/blob/87110e42eb4b4b99ef4ec09c97c6971e95f97ce7/README.md).

Standard captions are displayed as one paragraph of up to 300 characters, including an ellipsis when shortened. Markdown escaping counts toward the limit; emoji clusters and caption URLs are not split. The excerpt can be shorter when the surrounding message needs room. No full-caption text file is added; **Original post** opens the source caption. The complete available caption is still sent for translation. Native captions shown without translation remain controlled by the provider. A failed single-post preview keeps the original message and a tracked English-caption output. A mixed/multiple-post preview failure uses the existing rollback path. Only captions are translated: no image OCR, audio transcription or replacement media is produced. Manual `/fix` and Apps → Fix with Linky use the same available translation and server presentation choice. Messages already using rich translated X cards skip Instagram translation to preserve media.

`/settings instagram_presentation:compact` reduces the translated excerpt to 120 characters. `media-first` requests gallery media without a caption lookup, including when translation is off; a missing media preview cannot be counted as a delivered translated caption. `standard` preserves the default. The presets retain attribution and controls, and native captions in untranslatable Standard/Compact posts remain provider-controlled.

## Observed example

On September 11, 2026, public post `DdFwAIqgncQ` returned a full mixed English/Estonian caption, including hard-wrapped Estonian lines. The API returned `GraphImage`, but normal, gallery and direct preview modes all advertised the same inaccessible static Instagram resource. A GET failed with `Unsigned URL`. Its caption is available for translation; its image needs a working upstream media source. The native Discord description is truncated, so it must not be used as if it contained the complete caption.

On September 12, OGInstagram gallery previews returned the correct image for `DdKVPMEhTXe` and video metadata for `DdFKS1ABmK4` using both `/reel/` and `/reels/` routes in Discord, without the original caption. All temporary provider-check messages were removed. Caption metadata still comes from Instagram7; OGInstagram HTTP requests from the bot host were blocked even when Discord could embed its links, so it is not used as a caption metadata source.

On November 18, 2026, `fkinstagram.com` no longer resolved, so the Instagram7 caption route was unreachable; Linky now reads captions from OGInstagram. From the bot host, OGInstagram returned HTTP 200 Notes within 0.3 seconds for public post `DeIfsDPo0zx` (one `image/jpeg` attachment) and Reel `DdFKS1ABmK4` (one `video/mp4`), under both `/p/` and `/reel/`. A missing shortcode and the `/tv/` route returned HTTP 404 problem documents, and post `DdKVPMEhTXe` returned HTTP 503. These eight requests carried only public shortcodes; they did not exercise Google translation, Discord rendering or playback.

Those observations concern these posts at the time of testing. A successful metadata request or `GraphImage` hint does not establish working media. Automated tests use synthetic captions and media URLs, and cannot establish Google translation accuracy or Discord playback.

## Activation checks

1. Complete the billing, dedicated key and quota setup in the [self-hosting guide](self-hosting.md). Keep Instagram translation disabled until the key is restricted and the daily Cloud quota is set. Preserve the usage journal across restarts. Publish the caption-processing privacy notice before enabling hosted translation.
2. With the real API, check a mixed English/Estonian caption, an English-only caption and paragraphs with hard wraps, handles, URLs and hashtags. Confirm all foreign prose is translated and tokens remain intact. API failure, unknown language and an exhausted budget must leave normal preview handling available.
3. In an authorized Discord test channel, check a healthy image, Reel and video posted through `/p/`. Confirm one block with the source-language label, no duplicate author or original caption, intact image/player and actual playback. Native video metadata alone is insufficient proof of playback.
4. Check a post with broken upstream media. Its original must remain, with one English-caption output and working Original post/Remove controls. Edit or delete the source and verify the tracked output follows it.
5. Disable `/settings translate_instagram`, disable Instagram, and change source text while lookup is pending. No stale translated output should remain. Test Replace and Reply modes without broadening server/channel scope.
6. Confirm long captions have a short excerpt and a visible language label without a text attachment, including captions with emoji or a URL longer than the excerpt. Confirm caption URLs never create extra embeds or override the gallery preview expectation.

Self-hosted instances default to translation off. Hosted Linky has caption translation enabled as of September 15, 2026; each server can disable it in `/settings`. Repeat the API and Discord checks above after changes to this integration. Provider-gallery checks alone do not establish translation accuracy.
