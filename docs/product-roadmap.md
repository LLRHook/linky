# Linky product roadmap

Reviewed September 17, 2026. All seven priorities below are **Planned**. They are ordered proposals, with no promised delivery dates. The [competitor and user-gap research](growth-research-2026-09-17.md) links to the primary evidence and separates individual requests from broader demand assumptions.

## Product scope and shipped foundation

The hosted service focuses on Instagram, TikTok, X/Twitter, YouTube, Bluesky, Reddit and Twitch clips, including the available English translations and YouTube extras. Erome is disabled across the hosted application. Supported Erome video and image albums remain available to operators running their own instance and infrastructure. Confirm the deployed scope before submitting a directory listing; this policy does not establish Discord App Directory eligibility.

Linky already has private setup and diagnosis, channel selection, Reply/Replace, personal commands, per-platform switches, Original post, owner-only Remove, per-message bypass, reply synchronization, matching-preview checks, bounded recovery and shared public Retry/Details controls. Compact translated Instagram captions, YouTube display choices and private counts/comment replies are also shipped. Self-hosted media has fair bounded scheduling, progress, validated reuse and album loading. These are the foundation, not new backlog items. See [delivery reliability](delivery-reliability.md), the [current README](../README.md) and [public supported links](https://linkybot.dev/supported-platforms) for limits.

The seven-day Details history is for individual investigations. The separate operator archive defaults to 30 days within 64 MiB and omits Discord identities, message contents and URLs. Both are distinct from size-rotated Docker logs and optional website analytics. The [operator reliability guide](operator-reliability.md) defines collection and reporting; an observed delivery check does not establish client playback.

## Planned priorities

Relative cost describes engineering and continuing maintenance, not a time estimate. Impact is a hypothesis to check with hosted telemetry and willing admins. Preserve source-deletion checks, ownership, bounded requests and documented privacy limits in every change.

| Priority and status | Proposed addition and acceptance criteria | Relative cost / expected impact |
| --- | --- | --- |
| 1. Ordinary-platform reliability coverage (Planned) | Extend existing diagnostics with a repeatable corpus covering text, video, GIF, galleries, unavailable posts and intentional suppression. Separate URL recognition, Discord metadata and observed client playback. Publish only a dated, qualified status summary with sample counts, failures and coverage; test stale observations and upstream failure classification. Reuse the existing report tools. | Medium, continuing fixture/network cost; high trust and support potential. No comparative uptime advantage established. |
| 2. Safe mobile share links (Planned) | Start with Instagram `/share/`, then evaluate Reddit app/short links. Resolve only allowed HTTPS destinations with public-address checks at every hop, fixed redirect/time/byte caps and no cookies or arbitrary endpoints. Normalize to a supported post. Test loops, hostile destinations, unavailable posts and preservation on failure; verify real public URL forms separately. | Medium, continuing redirect maintenance; potentially high completion benefit within existing platforms. |
| 3. Persistent personal opt-out (Planned) | Add a private, reversible per-server preference for automatic fixing. Keep deliberate manual actions documented and distinct. Define precedence and thread behavior; persist only necessary IDs/preferences with deletion and retention rules. Test restart, edits and races. Consider limited role/category exclusions later if admins request them. | Medium with a small new data-retention obligation; high control/trust potential. Per-message `!nolinky` already works. |
| 4. First-success setup checks (Planned) | Improve the saved-state/readiness summary and show faithful Reply/Replace examples. Report effective channels and missing permissions. Any public test post requires an explicit test action. Use a permissioned admin trial to record confusing steps, completion time and assistance; fix observed problems without claiming statistical significance. | Small to medium; high activation potential. This extends existing `/setup` and `/diagnose`, without adding a dashboard. |
| 5. A small presentation preset (Planned) | Pilot compact/media-first presentation on one tested provider mode. Show a faithful example; preserve attribution, media, Original post and Remove ownership. Test missing captions, translation off and unavailable media. Explain provider-controlled native captions. Avoid arbitrary templates; treat quiet notification behavior separately from mention suppression. | Medium, provider-mode maintenance; moderate potential to reduce clutter. The 300-character translated Instagram excerpt is already shipped. |
| 6. One target-language pilot (Planned) | Ask willing admins which language they need before choosing a locale. Pilot one opt-in target, validate script variants, key caches by target and expose availability/quota limits. Preserve the preview on translation failure. Do not promise OCR, audio translation or every language. | Medium, API quota and locale testing; uncertain audience expansion. English is already supported. |
| 7. Evaluate YouTube community posts (Planned) | Test public image/text posts, supported URL forms, unavailable posts, creator attribution and media order. Require bounded transport/parsing and actual client checks before enabling or advertising. Defer if pilot admins do not use it. | Medium to large, continuing provider/parser cost; uncertain demand. Existing video counts do not cover community posts. |

## Review cadence and promotion

Begin a weekly review after the first complete week of hosted archive collection. Check dates, missing days, queue/storage losses and capacity effects before comparing outcomes. Report platform/path/outcome counts with denominators and stage/cache observations where available. These are instrumented attempts; they are not a census of all links or users. Small groups and selected release samples do not establish production percentiles.

Choose one bounded change using those observations and voluntary admin feedback. Record its hypothesis, acceptance cases and result, including failures, at the next review. No usage, conversion, growth or latency goal is invented here. The archive excludes Discord identities, so it cannot measure returning-server cohorts or connect website invite clicks to installation and a first successful preview.

Prepare dated, non-adult demonstrations of ordinary previews, English translation and YouTube details before seeking wider placement. Keep claims consistent with deployed scope and credit upstream providers. Directory eligibility, reviewer permissions and community rules need a fresh check before submission. Relevant recommendation replies should disclose authorship; do not use unsolicited bot DMs, competitor issue advertisements, fake reviews or automated voting. The [growth research](growth-research-2026-09-17.md#promotion-gates-and-community-rules) gives the primary rules and a proposed promotion sequence. External posts, directory submissions and paid placements require separate authorization.

A dashboard, arbitrary fixer endpoints, a large platform expansion and a new translation engine are deferred. Additional regional media experiments belong to self-hosted media work, not this hosted growth plan. The weekly review is a documented cadence; no scheduler or external campaign is created by this document.
